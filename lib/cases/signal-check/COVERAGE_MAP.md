# Signal Check coverage map

Read this together with `SIGNAL_CHECK_CHECKLIST.md`, rule 8: this map uses
each standard's existing Group Chat `trapLine` only to judge whether the
standard is fertile ground for a Signal Check case (a believable claim +
concrete evidence). It is NOT a source to copy from — a new Signal Check
case gets a freshly written claim/scenario, never the Group Chat trap
line reworded into a new wrapper.

**Candidacy key:**
- **Strong** — clear, believable, testable false claim; evidence could
  plausibly be shown in a photo/data log; maps well to True/Misleading/False.
- **Maybe** — plausible but needs real reshaping (too abstract, or the
  evidence doesn't obviously split into 3-4 discrete signals).
- **Skip** — too procedural/abstract/values-based for a claim-verdict
  format; no natural false belief to test. Leave as Group Chat only.
- **Already exists** — a live Signal Check case already covers this
  standard.

**Totals across all 149 standards reviewed: 114 Strong, 24 Maybe, 6 Skip,
5 Already exist.**
